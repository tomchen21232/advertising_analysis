# Meta 廣告成效儀表板

純前端 HTML 儀表板。上傳的檔案決定顯示哪些區塊：

| 上傳 | 顯示 |
|---|---|
| 只有 Meta 廣告匯出檔 | 廣告成效（KPI、花費排行、重點警示、明細） |
| 只有診所預約資料 | 預約與到店（到店率、每日、依客戶來源） |
| 兩份都有 | 以上兩者＋「廣告 → 預約 → 到店」：**Meta 預約率**、Meta 到店率、每筆預約成本 |

投手填寫表為選填。

## 使用方式

網頁本身不存放任何廣告資料。每次打開網頁後：

1. Meta 廣告管理員 → 廣告層級 → 選日期區間 → 「報表 → 匯出表格資料」→ 下載 CSV（不用轉 xlsx）。
   - 建議欄位加上「廣告編號」「連結點擊次數」「CTR」；細分選「依時間 → 天」可看趨勢。
2. 打開儀表板網頁，把 CSV 拖進頁面（或按「選擇檔案」）。
3. 投手填寫表 `pitcher_input.xlsx`（選填）可以和 CSV 一起選，範本在 `templates/`。

檔案只在瀏覽器內讀取，不會上傳；重新整理頁面即清除。

> 進階：若之後想讓網頁自動讀檔，把檔案放到 `data/meta_ads.csv`（或 .xlsx）與 `data/pitcher_input.xlsx`，網頁會優先讀取。

## 預約資料

診所系統匯出的預約 Excel，第一個工作表需要有「預約時間」「報到狀態」「客戶來源」欄位（另會讀「電話去識別化」「姓名去識別化」「新舊客」「診所」）。系統看到「報到狀態＋預約時間」就自動判定為預約檔。

- **預約人次**：同一客戶同一天算 1 次（「諮詢＋療程」兩列只算一次）
- **到店**：報到狀態不是「未報到」即算到店
- **已結算**：今天以前、且狀態已回填的日子；最近幾天若全部是「未報到」會判定為「狀態待確認」，不算進到店率

## Meta 預約率與到店率

- **Meta 預約率** ＝ 客戶來源為 Facebook／Instagram 的預約人次 ÷ 私訊對話數（點擊或看過廣告的人數，Meta 後台數據）
- **Meta 到店率** ＝ Meta 預約且已到店 ÷ Meta 預約（只算已結算的日子）
- 只比對廣告期間內的預約；預約檔只有單一診所時，「廣告分店」會自動選名稱相符的分店
- 「尚未確認」來源的客人可能也是廣告客，所以 Meta 數字是下限
- 「Meta」包含哪些來源寫在 `CONFIG.metaSources`

## 投手填寫表（pitcher_input.xlsx）

| 工作表 | 誰填 | 填什麼 |
|---|---|---|
| 廣告補充 | 投手 | 每支廣告的階段、素材類型、投手、素材連結、卡關／下一步（可指定療程） |
| 療程對照 | PM | 廣告名稱關鍵字 → 療程，新療程加一列即可 |

Meta 後台已有的數字（花費、曝光、成果…）一律不手填。

## 命名規則

廣告組合名稱：`目標-形式｜分店｜受眾類型｜受眾`，例：`轉換-訊息｜新店｜興趣｜美妝`。
不符合規則的組合會在「資料品質檢查」列出。

## 可見範圍

頁面已設定 `noindex`，搜尋引擎不會收錄。但 GitHub Pages 本身沒有登入機制：知道網址的人都能開網頁，但網頁不含任何廣告資料，資料只存在上傳者自己的瀏覽器。
